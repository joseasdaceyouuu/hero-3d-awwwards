   479→
   480→Graphiti is a framework for building and querying temporal context graphs for AI agents. Unlike static knowledge graphs,
   481→Graphiti's context graphs track how facts change over time, maintain provenance to source data, and support both
   482→prescribed and learned ontology — making them purpose-built for agents operating on evolving, real-world data.
   483→
   484→Unlike traditional retrieval-augmented generation (RAG) methods, Graphiti continuously integrates user interactions,
   485→structured and unstructured enterprise data, and external information into a coherent, queryable graph. The framework
   486→supports incremental data updates, efficient retrieval, and precise historical queries without requiring complete graph
   487→recomputation, making it suitable for developing interactive, context-aware AI applications.
   488→
   489→Use Graphiti to:
   490→
   491→Build context graphs that evolve with every interaction — tracking what's true now and what was true before.
   492→
   493→Give agents rich, structured context instead of flat document chunks or raw chat history.
   494→
   495→Query across time, meaning, and relationships with hybrid retrieval (semantic + keyword + graph traversal).
   496→
   497→ 
   498→
   499→ 
   500→
   501→What is a Context Graph?
   502→
   503→A context graph is a temporal graph of entities, relationships, and facts — like "Kendra loves Adidas shoes (as of
   504→March 2026)." Unlike traditional knowledge graphs, each fact in a context graph has a validity window: when it became
   505→true, and when (if ever) it was superseded. Entities evolve over time with updated summaries. Everything traces back to
   506→episodes — the raw data that produced it.
   507→
   508→What makes Graphiti unique is its ability to autonomously build context graphs from unstructured and structured data,
   509→handling changing relationships while preserving full temporal history.
   510→
   511→A context graph contains:
   512→
   513→Component
   514→What it stores
   515→
   516→Entities (nodes)
   517→People, products, policies, concepts — with summaries that evolve over time
   518→
   519→Facts / Relationships (edges)
   520→Triplets (Entity → Relationship → Entity) with temporal validity windows
   521→
   522→Episodes (provenance)
   523→Raw data as ingested — the ground truth stream. Every derived fact traces back here
   524→
   525→Custom Types (ontology)
   526→Developer-defined entity and edge types via Pydantic models
   527→
   528→Graphiti and Zep
   529→
   530→Graphiti is the open-source temporal context graph engine at the core of
   531→Zep's context infrastructure for AI agents. Zep manages context graphs at scale, providing
   532→governed, low-latency context retrieval and assembly for production agent deployments.
   533→
   534→Using Graphiti, we've demonstrated Zep is
   535→the State of the Art in Agent Memory.
   536→
   537→Read our paper: Zep: A Temporal Knowledge Graph Architecture for Agent Memory.
   538→
   539→We're excited to open-source Graphiti, believing its potential as a context graph engine reaches far beyond memory
   540→applications.

   582→Why Graphiti?
   583→
   584→Traditional RAG approaches often rely on batch processing and static data summarization, making them inefficient for
   585→frequently changing data. Graphiti addresses these challenges by providing:
   586→
   587→Temporal Fact Management: Facts have validity windows. When information changes, old facts are
   588→invalidated — not deleted. Query what's true now, or what was true at any point in time.
   589→
   590→Episodes & Provenance: Every entity and relationship traces back to the episodes (raw data) that produced it.
   591→Full lineage from derived fact to source.
   592→
   593→Prescribed & Learned Ontology: Define entity and edge types upfront via Pydantic models (prescribed), or let
   594→structure emerge from your data (learned). Start simple, evolve as patterns appear.
   595→
   596→Incremental Graph Construction: New data integrates immediately without batch recomputation. The graph evolves
   597→in real-time as episodes are ingested.
   598→
   599→Hybrid Retrieval: Combines semantic embeddings, keyword (BM25), and graph traversal for low-latency,
   600→high-precision queries without reliance on LLM summarization.
   601→
   602→Scalability: Efficiently manages large datasets with parallel processing, pluggable graph backends, suitable
   603→for enterprise workloads.

   654→Installation
   655→
   656→Requirements:
   657→
   658→Python 3.10 or higher
   659→
   660→Neo4j 5.26 / FalkorDB 1.1.2 / Amazon Neptune Database Cluster or Neptune Analytics Graph + Amazon OpenSearch
   661→Serverless collection (serves as the full text search backend) / Kuzu 0.11.2 (deprecated, see below)
   662→
   663→OpenAI API key (Graphiti defaults to OpenAI for LLM inference and embedding)
   664→
   665→Important
   666→
   667→Graphiti works best with LLM services that support Structured Output (such as OpenAI, Anthropic, and Gemini).
   668→Using other services may result in incorrect output schemas and ingestion failures. This is particularly
   669→problematic when using smaller models.
   670→
   671→Optional:
   672→
   673→Google Gemini, Anthropic, or Groq API key (for alternative LLM providers)

   747→Default to Low Concurrency; LLM Provider 429 Rate Limit Errors
   748→
   749→Graphiti's ingestion pipelines are designed for high concurrency. By default, concurrency is set low to avoid LLM
   750→Provider 429 Rate Limit Errors. If you find Graphiti slow, please increase concurrency as described below.
   751→
   752→Concurrency controlled by the SEMAPHORE_LIMIT environment variable. By default, SEMAPHORE_LIMIT is set to 10
   753→concurrent operations to help prevent 429 rate limit errors from your LLM provider. If you encounter such errors, try
   754→lowering this value.
   755→
   756→If your LLM provider allows higher throughput, you can increase SEMAPHORE_LIMIT to boost episode ingestion
   757→performance.

   759→Quick Start
   760→
   761→Important
   762→
   763→Graphiti defaults to using OpenAI for LLM inference and embedding. Ensure that an OPENAI_API_KEY is set in your
   764→environment.
   765→Support for Anthropic, Gemini, and Groq is available, too. Other LLM providers — both hosted OpenAI-compatible APIs
   766→(DeepSeek, Together, OpenRouter, …) and local servers (Ollama, vLLM, llama.cpp, LM Studio) — may be used via their
   767→OpenAI-compatible endpoints; see
   768→Using Graphiti with OpenAI-compatible providers and local LLMs.
   769→
   770→For a complete working example, see the Quickstart Example in the examples directory.
   771→The quickstart demonstrates:
   772→
   773→Connecting to a Neo4j, Amazon Neptune, FalkorDB, or Kuzu database
   774→
   775→Initializing Graphiti indices and constraints
   776→
   777→Adding episodes to the graph (both text and structured JSON)
   778→
   779→Searching for relationships (edges) using hybrid search
   780→
   781→Reranking search results using graph distance
   782→
   783→Searching for nodes using predefined search recipes
   784→
   785→The example is fully documented with clear explanations of each functionality and includes a comprehensive README with
   786→setup instructions and next steps.
   787→

   804→MCP Server
   805→
   806→The mcp_server directory contains a Model Context Protocol (MCP) server implementation for Graphiti. This server
   807→allows AI assistants to interact with Graphiti's context graph capabilities through the MCP protocol.
   808→
   809→Key features of the MCP server include:
   810→
   811→Episode management (add, retrieve, delete)
   812→
   813→Entity management and relationship handling
   814→
   815→Semantic and hybrid search capabilities

   838→Database Configuration
   839→
   840→Database names are configured directly in the driver constructors:
   841→
   842→Neo4j: Database name defaults to neo4j (hardcoded in Neo4jDriver)
   843→

   847→to the Graphiti constructor using the graph_driver parameter.

   856→uri="bolt://localhost:7687",
   857→user="neo4j",
   858→password="password",
   859→database="my_custom_database" # Custom database name
   860→)
   861→
   862→# Pass the driver to Graphiti
   863→graphiti = Graphiti(graph_driver=driver)

   921→Using Graphiti with Azure OpenAI
   922→
   923→Graphiti supports Azure OpenAI for both LLM inference and embeddings using Azure's OpenAI v1 API compatibility layer.
   924→
   925→Quick Start
   926→
   927→from openai import AsyncOpenAI
   928→from graphiti_core import Graphiti
   929→from graphiti_core.llm_client.azure_openai_client import AzureOpenAILLMClient
   930→from graphiti_core.llm_client.config import LLMConfig
   931→from graphiti_core.embedder.azure_openai import AzureOpenAIEmbedderClient
   932→
   933→# Initialize Azure OpenAI client using the standard OpenAI client
   934→# with Azure's v1 API endpoint
   935→azure_client = AsyncOpenAI(
   936→base_url="https://your-resource-name.openai.azure.com/openai/v1/",
   937→api_key="your-api-key",
   938→)
   939→
   940→# Create LLM and Embedder clients
   941→llm_client = AzureOpenAILLMClient(
   942→azure_client=azure_client,
   943→config=LLMConfig(model="gpt-5-mini", small_model="gpt-5-mini") # Your Azure deployment name
   944→)
   945→embedder_client = AzureOpenAIEmbedderClient(
   946→azure_client=azure_client,
   947→model="text-embedding-3-small" # Your Azure embedding deployment name
   948→)
   949→
   950→# Initialize Graphiti with Azure OpenAI clients
   951→graphiti = Graphiti(
   952→"bolt://localhost:7687",
   953→"neo4j",
   954→"password",
   955→llm_client=llm_client,
   956→embedder=embedder_client,
   957→)
   958→
   959→# Now you can use Graphiti with Azure OpenAI
   960→
   961→Key Points:
   962→
   963→Use the standard AsyncOpenAI client with Azure's v1 API endpoint format:
   964→https://your-resource-name.openai.azure.com/openai/v1/
   965→
   966→The deployment names (e.g., gpt-5-mini, text-embedding-3-small) should match your Azure OpenAI deployment names
   967→
   968→See examples/azure-openai/ for a complete working example
   969→
   970→Make sure to replace the placeholder values with your actual Azure OpenAI credentials and deployment names.
   971→
   972→Using Graphiti with Google Gemini
   973→
   974→Graphiti supports Google's Gemini models for LLM inference, embeddings, and cross-encoding/reranking. To use Gemini,
   975→you'll need to configure the LLM client, embedder, and the cross-encoder with your Google API key.
   976→
   977→Install Graphiti:
   978→
   979→uv add "graphiti-core[google-genai]"
   980→
   981→# or
   982→
   983→pip install "graphiti-core[google-genai]"
   984→
   985→from graphiti_core import Graphiti
   986→from graphiti_core.llm_client.gemini_client import GeminiClient, LLMConfig
   987→from graphiti_core.embedder.gemini import GeminiEmbedder, GeminiEmbedderConfig
   988→from graphiti_core.cross_encoder.gemini_reranker_client import GeminiRerankerClient
   989→
   990→# Google API key configuration
   991→api_key = "<your-google-api-key>"
   992→
   993→# Initialize Graphiti with Gemini clients
   994→graphiti = Graphiti(
   995→"bolt://localhost:7687",
   996→"neo4j",
   997→"password",
   998→llm_client=GeminiClient(
   999→config=LLMConfig(
  1000→api_key=api_key,
  1001→model="gemini-2.0-flash"
  1002→)
  1003→),
  1004→embedder=GeminiEmbedder(
  1005→config=GeminiEmbedderConfig(
  1006→api_key=api_key,
  1007→embedding_model="embedding-001"
  1008→)
  1009→),
  1010→cross_encoder=GeminiRerankerClient(
  1011→config=LLMConfig(
  1012→api_key=api_key,
  1013→model="gemini-2.5-flash-lite"
  1014→)
  1015→)
  1016→)
  1017→
  1018→# Now you can use Graphiti with Google Gemini for all components
  1019→
  1020→The Gemini reranker uses the gemini-2.5-flash-lite model by default, which is optimized for
  1021→cost-effective and low-latency classification tasks. It uses the same boolean classification approach as the OpenAI
  1022→reranker, leveraging Gemini's log probabilities feature to rank passage relevance.

  1024→Using Graphiti with OpenAI-compatible providers and local LLMs
  1025→
  1026→Graphiti can use any OpenAI-compatible /v1 endpoint for LLM inference via OpenAIGenericClient — both hosted
  1027→providers (DeepSeek, Together, OpenRouter, Fireworks, etc.) and local servers (Ollama, vLLM, llama.cpp, LM
  1028→Studio). Local servers are ideal for privacy-focused applications or avoiding API costs. The example below uses Ollama;
  1029→for any other provider, point base_url at its endpoint and set the appropriate api_key and model.
  1030→
  1031→Note: Use OpenAIGenericClient (not OpenAIClient) for these endpoints. It is optimized for local models with a
  1032→higher default max token limit (16K vs 8K) and handles structured outputs across compatible providers.
  1033→
  1034→Install the models:
  1035→
  1036→ollama pull deepseek-r1:7b # LLM
  1037→ollama pull nomic-embed-text # embeddings
  1038→
  1039→from graphiti_core import Graphiti
  1040→from graphiti_core.llm_client.config import LLMConfig
  1041→from graphiti_core.llm_client.openai_generic_client import OpenAIGenericClient
  1042→from graphiti_core.embedder.openai import OpenAIEmbedder, OpenAIEmbedderConfig
  1043→from graphiti_core.cross_encoder.openai_reranker_client import OpenAIRerankerClient
  1044→
  1045→# Configure Ollama LLM client
  1046→llm_config = LLMConfig(
  1047→api_key="ollama", # Ollama doesn't require a real API key, but some placeholder is needed
  1048→model="deepseek-r1:7b",
  1049→small_model="deepseek-r1:7b",
  1050→base_url="http://localhost:11434/v1", # Ollama's OpenAI-compatible endpoint
  1051→)
  1052→
  1053→llm_client = OpenAIGenericClient(config=llm_config)
  1054→
  1055→# Initialize Graphiti with Ollama clients
  1056→graphiti = Graphiti(
  1057→"bolt://localhost:7687",
  1058→"neo4j",
  1059→"password",
  1060→llm_client=llm_client,
  1061→embedder=OpenAIEmbedder(
  1062→config=OpenAIEmbedderConfig(
  1063→api_key="ollama", # Placeholder API key
  1064→embedding_model="nomic-embed-text",
  1065→embedding_dim=768,
  1066→base_url="http://localhost:11434/v1",
  1067→)
  1068→),
  1069→cross_encoder=OpenAIRerankerClient(client=llm_client, config=llm_config),
  1070→)
  1071→
  1072→# Now you can use Graphiti with local Ollama models
  1073→
  1074→Ensure Ollama is running (ollama serve) and that you have pulled the models you want to use.
  1075→
  1076→Structured output and small models
  1077→
  1078→Graphiti depends on structured (JSON) output for entity/edge extraction and deduplication, and works best with models
  1079→and providers that reliably honor it (OpenAI, Anthropic, Gemini). Reliability varies across OpenAI-compatible providers and
  1080→especially on smaller or local models, so OpenAIGenericClient exposes a structured_output_mode:
  1081→
  1082→"json_schema" (default): requests native structured output via response_format. Best on capable models and
  1083→providers that enforce the schema via constrained decoding.
  1084→
  1085→"json_object": requests plain-JSON mode and injects the schema into the prompt instead. Use this for
  1086→providers/models that don't reliably honor json_schema — including some local servers that accept the json_schema
  1087→request but don't actually constrain output to it, where json_object can be more reliable.
  1088→
  1089→When using smaller or local models:
  1090→
  1091→Prefer the most capable model you can run. Very small models frequently emit JSON that doesn't match the requested
  1092→schema, which surfaces as extraction failures.
  1093→
  1094→Responses wrapped in Markdown ```json code fences are stripped automatically.
  1095→
  1096→Keep SEMAPHORE_LIMIT low (see above) — local
  1097→servers and some providers have limited concurrency.

  1112→What We Collect
  1113→
  1114→When you initialize a Graphiti instance, we collect:
  1115→
  1116→Anonymous identifier: A randomly generated UUID stored locally in ~/.cache/graphiti/telemetry_anon_id
  1117→
  1118→System information: Operating system, Python version, and system architecture
  1119→
  1120→Graphiti version: The version you're using
  1121→
  1122→Configuration choices:
  1123→
  1124→LLM provider type (OpenAI, Azure, Anthropic, etc.)
  1125→
  1126→Database backend (Neo4j, FalkorDB, Kuzu, Amazon Neptune Database or Neptune Analytics)
  1127→
  1128→Embedder provider (OpenAI, Azure, Voyage, etc.)
  1129→
  1130→What We Don't Collect
  1131→
  1132→We are committed to protecting your privacy. We never collect:
  1133→
  1134→Personal information or identifiers
  1135→
  1136→API keys or credentials
  1137→
  1138→Your actual data, queries, or graph content
  1139→
  1140→IP addresses or hostnames
  1141→
  1142→File paths or system-specific information
  1143→
  1144→Any content from your episodes, nodes, or edges
  1145→
  1146→Why We Collect This Data
  1147→
  1148→This information helps us:
  1149→
  1150→Understand which configurations are most popular to prioritize support and testing
  1151→
  1152→Identify which LLM and database providers to focus development efforts on
  1153→
  1154→Track adoption patterns to guide our roadmap
  1155→
  1156→Ensure compatibility across different Python versions and operating systems
  1157→
  1158→By sharing this anonymous information, you help us make Graphiti better for everyone in the community.

  1164→How to Disable Telemetry
  1165→
  1166→Telemetry is opt-out and can be disabled at any time. To disable telemetry collection:
  1167→
  1168→Option 1: Environment Variable
  1169→
  1170→export GRAPHITI_TELEMETRY_ENABLED=false
  1171→
  1172→Option 2: Set in your shell profile
  1173→
  1174→# For bash users (~/.bashrc or ~/.bash_profile)
  1175→echo 'export GRAPHITI_TELEMETRY_ENABLED=false' >> ~/.bashrc
  1176→
  1177→# For zsh users (~/.zshrc)
  1178→echo 'export GRAPHITI_TELEMETRY_ENABLED=false' >> ~/.zshrc

  1180→Option 3: Set for a specific Python session
  1181→
  1182→import os
  1183→
  1184→os.environ['GRAPHITI_TELEMETRY_ENABLED'] = 'false'
  1185→
  1186→# Then initialize Graphiti as usual
  1187→from graphiti_core import Graphiti
  1188→
  1189→graphiti = Graphiti(...)
